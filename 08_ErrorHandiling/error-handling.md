# Handling Errors and Exceptions in Javascript

## What is an Error in JavaScript

An error is a problem that occurs while a JavaScript program is running and it prevents program from completing its execution. Errors happen at when JavaScript cannot understand or execute a piece of code like dividing by zero causes an error.

Common causes:

* Invalid syntax
* Using undefined variables
* Wrong function usage
* Network failures
* File or database access problems

When an error occurs, JavaScript creates an Error object and stops the normal flow of the program.

## What is an Exception in JavaScript

An exception is an error that is intentionally generated by the program using the `throw` statement.

It is a way for developers to signal that something went wrong and should be handled  like checking input from used and using `throw` to report invalid input creates an exception.

### Why Exceptions are Used

* To stop invalid program execution
* To show meaningful error messages
* To safely control program flow
* To allow error handling using try/catch

### Relationship Between Error and Exception

| Error                              | Exception                 |
| ---------------------------------- | ------------------------- |
| Happens automatically              | Thrown manually           |
| Created by JavaScript              | Created by the developer  |
| Can crash the program if unhandled | Can be caught and handled |

# Compile Time and Runtime

## Compile Time

Compile time is the stage when your source code is checked and translated before the program actually runs.

During compile time:

* Syntax is checked
* Errors like missing brackets, wrong keywords, and invalid structure are found
* Code is prepared for execution

These errors are called compile-time errors.

Example in words:
If you forget a closing brace or type a keyword incorrectly, the error is found before the program runs.

## Run Time

Run time is the stage when the program is actually executing.

During run time:

* Code is executed line by line
* Variables get values
* Functions run
* API calls, file operations, and database operations happen

Errors that occur here are called run-time errors.

Example in words:
Dividing by zero, accessing undefined variables, or network failures happen while the program is running.



### Difference

| Compile Time           | Run Time                        |
| ---------------------- | ------------------------------- |
| Before execution       | During execution                |
| Checks code structure  | Executes code                   |
| Finds syntax errors    | Finds logical and system errors |
| Program does not start | Program crashes while running   |


# Categories of Runtime Errors

## 1. Reference Errors

Happen when you try to use a variable or function that does not exist or is not defined.

Example in words:
Using a variable before declaring it.



## 2. Type Errors

Occur when an operation is performed on the wrong data type.

Example in words:
Trying to call something that is not a function, or accessing properties of `null` or `undefined`.



## 3. Range Errors

Happen when a value is not within the allowed range.

Example in words:
Creating an array with an invalid length.



## 4. Syntax Errors at Runtime

Occur when JavaScript finds invalid code while executing dynamically generated code.

Example in words:
Errors inside `eval()`.



## 5. URI Errors

Occur when incorrect encoding or decoding of URLs is performed.

Example in words:
Using malformed URI components.



## 6. Logical Errors

These do not stop the program but produce wrong output.

Example in words:
Wrong calculation results due to incorrect conditions.

# JavaScript Error Handling – Complete Production Guide

Error handling is the backbone of reliable, secure, and user‑friendly applications. In real production systems, error handling is not only about preventing crashes, but also about logging, monitoring, graceful recovery, and user experience.

---

## 1. Types of Errors in JavaScript

JavaScript errors generally fall into two main categories:

• Compile-time errors – Errors detected while parsing the code (mostly SyntaxError).
• Runtime errors – Errors that occur while the program is running.

| Error Type     | Description                  | Example           |
| -------------- | ---------------------------- | ----------------- |
| SyntaxError    | Code is written incorrectly  | Missing `)`       |
| ReferenceError | Variable not defined         | `console.log(x)`  |
| TypeError      | Wrong operation on data type | `5.toUpperCase()` |
| RangeError     | Number out of allowed range  | `new Array(-1)`   |
| URIError       | Invalid URI methods          | `decodeURI("%")`  |
| EvalError      | Related to eval()            | Rare              |

Production Insight:
Most production crashes are caused by TypeError and ReferenceError. Static code analysis, TypeScript, and runtime validation dramatically reduce such errors.

---

## 2. try...catch Block

Used to handle runtime exceptions and prevent application crashes.

```js
try {
    // risky code
} catch (error) {
    // runs if error occurs
}
```

```js
try {
    let x = y + 5;   // y is not defined
} catch (error) {
    console.log("Error occurred:", error.message);
}
```

Production Insight:
Use try/catch only around risky logic. Wrapping entire files in try/catch hides real bugs and makes debugging difficult.

---

## 3. Catching Specific Errors

```js
try {
    let num = 10;
    num();    // TypeError
} catch (error) {
    if (error instanceof TypeError) {
        console.log("Type error found!");
    } else {
        console.log("Unknown error!");
    }
}
```

Production Insight:
This is heavily used in payment gateways, authentication systems, and API integrations where different failures require different recovery actions.

---

## 4. finally Block

```js
try {
    console.log("Opening file...");
    throw new Error("File corrupted");
} catch (err) {
    console.log("Error:", err.message);
} finally {
    console.log("Closing file...");
}
```

Production Insight:
Finally blocks are commonly used to stop loaders, close DB connections, and finalize transactions.

---

## 5. Throwing Custom Errors

```js
function withdraw(amount) {
    if (amount <= 0) {
        throw new Error("Invalid withdrawal amount");
    }
    console.log("Processing withdrawal:", amount);
}

try {
    withdraw(-500);
} catch (e) {
    console.log(e.message);
}
```

Production Insight:
Business rules (like invalid amount, missing credentials, expired sessions) are enforced using custom errors.

---

## 6. Creating Custom Error Classes

```js
class LoginError extends Error {
    constructor(message) {
        super(message);
        this.name = "LoginError";
    }
}

throw new LoginError("Password incorrect");
```

Custom error classes help categorize and log errors separately in monitoring tools like Sentry, Datadog, and New Relic.

---

## 7. Handling Promise Errors

```js
fetch("/api/data")
    .then(res => res.json())
    .then(data => console.log(data))
    .catch(err => console.log("Fetch failed:", err));
```

Production Insight:
Always attach `.catch()` to promises. Unhandled promise rejections crash Node servers.

---

## 8. Async/Await Error Handling

```js
async function getUser() {
    try {
        let res = await fetch("/api/user");
        let data = await res.json();
        console.log(data);
    } catch (error) {
        console.log("Request failed:", error.message);
    } finally {
        console.log("Request completed");
    }
}
```

---

## 9. Re-throwing Errors

```js
try {
    JSON.parse("invalid");
} catch (err) {
    console.log("Handled here");
    throw err;   // forward to global handler
}
```

Used when the function cannot fully resolve the issue and wants higher-level logic to decide.

---

## 10. Global Error Handling

```js
window.onerror = function (msg, url, line) {
    console.log("Global Error:", msg);
};
```

```js
process.on("uncaughtException", err => {
    console.log("Uncaught:", err.message);
});
```

## 11. Best Practices

• Always validate external data
• Never expose stack traces to users
• Log errors centrally
• Use monitoring services
• Fail gracefully

## 12. Real-World Example

async function payment(amount) {

# Creating Custom Errors

JavaScript allows you to create your own errors using the `Error` class.

You can define your own error message and throw it when something goes wrong.



## Using the built-in Error class

You create a new error object and throw it.

Concept in words:

* Create a new Error with a message
* Use `throw` to stop execution and send the error to `catch`



## Creating a Custom Error Class

You can create your own error type by extending the Error class.

This lets you define:

* Your own error name
* Custom messages
* Custom properties

This is useful when building large applications where different error types must be handled differently.



# Why Custom Errors Are Useful

* Provide clear error messages
* Help debugging
* Allow specific error handling
* Make code easier to maintain


```js
// Custom Error Class
class ValidationError extends Error {
    constructor(message) {
        super(message);
        this.name = "ValidationError";
    }
}

// Using the custom error
function checkAge(age) {
    if (age < 18) {
        throw new ValidationError("Age must be 18 or above");
    }
    return "Access Granted";
}

// Handling the custom error
try {
    console.log(checkAge(15));
} catch (err) {
    if (err instanceof ValidationError) {
        console.log("Validation Error:", err.message);
    } else {
        console.log("Other Error:", err.message);
    }
} finally {
    console.log("Validation check completed");
}
```
